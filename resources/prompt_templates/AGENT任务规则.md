# AGENT 任务规则

## 通用执行规则

1. 先读取当前项目的《当前任务.md》，只处理其中指定的项目和任务类型。
2. “原始需求”和“客户反馈”只读；所有产品版本统一写入“产品迭代”，客观执行历史追加到《项目记录.md》。客户明确认可后，最新有效 HTML 自然就是最终产品，不复制或改名为“最终交付版”。
3. 公共规范和工具统一从项目组根目录“公共工具”读取，不复制、覆盖或改写公共工具原件。
4. 默认不要读取其他项目；遇到资料缺失、含义不清或规则冲突时明确列出问题，不猜测客户意图。
5. 需求优先级为：当前任务特殊要求 > 当前轮最新客户反馈 > 此前已明确确认或修改的要求 > 原始需求 JSON > WORKFLOW.md > template.html。
6. 采用“最小必要修改 + 完整满足当前需求 + 必要回归验证”，不要无理由重构已经正常工作的部分。

## 首次制作

1. 先枚举“原始需求”中的全部文件；JSON 是结构化主需求，图片、PDF、Word、PPT、表格、Markdown 和其他文件是补充内容或视觉参考。
2. 读取当前工具能够读取的全部原始材料，不得遗漏图片或文档；无法读取的二进制材料必须在项目记录中写明文件名、原因和实际处理方式，不得假装已读取。
3. 读取“公共工具/WORKFLOW.md”，并以“公共工具/template.html”为制作起点。
4. 首次完整产物必须保存为《当前任务.md》指定的“产品迭代/课题名.html”；不得覆盖已经存在的历史产物。
5. 使用“公共工具/validate-tool.js”验证最终 HTML；验证失败时先修正再交付。
6. 遵循《当前任务.md》中的特殊要求；特殊要求为“无”时仅按通用规则和原始需求执行。
7. 完成后按“项目记录规则”更新《项目记录.md》中的“首次制作”记录。

## 反馈修改

1. 读取《当前任务.md》指定轮次下“客户反馈/第N轮/”的全部资料。
2. 读取《项目记录.md》作为历史索引，找到“产品迭代”中最新有效 HTML，并基于该版本修改。
3. 最新有效 HTML 以《项目配置.json》的 artifacts 和 HTML meta 为准；文件名仅用于兼容，不按修改时间猜测。不要从旧版本重新开始。
4. 读取原始需求核对基础目标，读取 WORKFLOW.md 获取现行制作规范，使用 validate-tool.js 验证。
5. 默认不要一次读取所有旧 HTML、全部历史截图或其他项目；只有核对某项历史要求时才针对性回看证据。
6. 第 N 轮产物必须保存为《当前任务.md》指定的“产品迭代/课题名（N）.html”，不得覆盖任何历史版本。
7. 完成后按“项目记录规则”追加本轮记录。

## 项目记录规则

1. 《项目记录.md》只记录客观历史，每完成一次执行就追加一次，不删除或改写旧记录。
2. 首次制作记录输入 JSON、输出路径、主要完成内容和验证结果。
3. 第 N 轮修改记录客户反馈来源、主要要求、实际修改、输出路径和验证结果。
4. 不写“客户满意”“等待审核”等无法由 Agent 确定的状态；客户是否满意只由用户判断。

## 产品版本规则

1. 首次版本命名为“课题名.html”，第 N 轮反馈版本命名为“课题名（N）.html”，具体名称以《当前任务.md》的预期输出为准。
2. 始终保留历史版本，不覆盖、不自动重命名，不按修改时间或文件大小猜测最新版本。
3. 如果目标文件已存在，停止写入并说明冲突，由用户确认后再处理。
4. 每个新版本使用《当前任务.md》预分配的新产物 ID，项目 ID 始终不变；UUID 不得拼入可见文件名。
5. 必须在 HTML 的 head 中写入以下不可见 meta，content 使用《当前任务.md》的实际值：
   - `<meta name="courseware-project-id" content="项目 ID">`
   - `<meta name="courseware-artifact-id" content="产物 ID">`
   - `<meta name="courseware-version" content="版本号">`
   - `<meta name="courseware-feedback-round" content="反馈轮次数字">`

## 验证规则

1. 每次制作或修改都运行 validate-tool.js，并检查页面可加载、交互和动画可用、控制台无关键错误。
2. 针对当前改动做必要回归检查，包括需求完整性、数学正确性、参数边界和常用分辨率。
3. 在《项目记录.md》中客观记录验证方式、结果和仍存在的问题。

## 项目记录身份规则

1. 首次制作记录项目显示名、项目 ID、产品文件名、产物 ID和版本 0。
2. 第 N 轮修改记录反馈轮次、产品文件名、产物 ID和版本 N。
3. 不在普通可见文件名中加入 UUID；稳定身份只写入项目配置、HTML meta和项目记录。
