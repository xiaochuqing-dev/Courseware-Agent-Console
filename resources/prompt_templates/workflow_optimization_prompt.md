# 工作流优化复盘

请基于以下已完成项目复盘课件制作工作流。第一轮只分析并输出报告，不直接修改任何公共文件。

## 读取范围

公共文件只读取一次：

1. AGENT 任务规则：{{RULES_PATH}}
2. 制作工作流：{{WORKFLOW_PATH}}
3. 默认模板：{{TEMPLATE_PATH}}
4. 验证工具：{{VALIDATOR_PATH}}

已选复盘项目：

{{SELECTED_PROJECTS}}

对每个项目先读取《项目记录.md》作为历史索引。只有分析某个具体问题时，才针对性读取原始需求、对应轮次客户反馈和对应产品版本。不要无目的遍历全部历史 HTML、截图或反馈，也不要重复读取公共文件。

## 分析目标

1. 第一版返工的直接原因是什么。
2. 哪些问题在多个项目中重复出现。
3. 哪些问题可以由 Agent 在制作前提前避免。
4. 哪些问题是 WORKFLOW.md 未明确约束导致的。
5. 哪些问题来自 template.html 的默认设计。
6. 哪些问题是 validate-tool.js 未覆盖的。
7. 哪些问题来自 AGENT任务规则.md 的不合理或冲突规则。
8. 哪些问题只是单一客户、知识点或项目的特例。

每个候选问题只能归入一个主要类别：

A. WORKFLOW.md
B. template.html
C. validate-tool.js
D. AGENT任务规则.md
E. 项目特例，不进入公共规则

避免把同一要求重复写入多个公共文件。优化目标是用更少、更准确的规则提高第一版成功率，而不是无限扩充工作流。

## 输出格式

一、当前工作流总体评价

二、高频返工问题

逐项列出问题、出现项目、证据和根因。

三、建议优化项

逐项列出应修改对象、建议内容、原因、收益、可能副作用和优先级（P0/P1/P2）。

四、不建议公共化的项目特例

五、建议保持不变的规则

六、最终结论

第一轮禁止修改 {{GROUP_ROOT}} 下的 AGENT任务规则.md、WORKFLOW.md、template.html 或 validate-tool.js。等待用户明确确认采纳条目后再实施。
