# P0 稳定性热修复报告

## 结论

本次修复解决了 JSON 后选覆盖前选、创建页入口同步阻塞、首页空状态缺少核心操作三个问题。真实创建、界面稳定性、重启恢复和原有阶段功能回归均已通过。

## 复现与根因

### 1. JSON 覆盖

复现方式：先选择 A/B/C.json，再选择 D/E/F.json。修复前列表只剩第二批文件。

根因：文件对话框已经使用 `QFileDialog.getOpenFileNames`，但回调执行 `self.json_files = [...]`，每次都用新结果整体替换已有列表。因此问题不在文件对话框，而在选择结果的状态更新方式。

### 2. 创建项目入口偶发卡顿

复现方式：创建页在初始化时已经检查公共工具，点击入口时 `MainWindow.show_create_page()` 又同步调用 `refresh_public_tools()`。该调用在 GUI 线程执行文件状态检查，并销毁、重建状态控件；资源路径受磁盘、打包目录或安全软件延迟时，页面切换会等待同样时间。

诊断探针：给资源检查注入 200 ms 延迟，修复前入口耗时约 201 ms，证明阻塞会直接传递到切页槽。代码检查未发现重复页面实例、重复信号连接或递归切页。

修复后同一探针结果：入口耗时 0.3 ms，资源检查总调用次数为 1，创建页对象始终复用。

### 3. 首页空状态

修复前主工作区是一张占满页面的白色卡片，仅提供“选择已有项目组”，缺少创建入口；同时只保存最近项目组，不保存该组最后选中的项目。

修复后去掉整页白卡，直接显示“创建新项目”和“选择已有项目组”两个核心操作。项目组加载时恢复该组最后选中的有效项目；记录失效时自动回退到第一个进行中项目。没有进行中项目时显示“查看已完成项目”。

## 具体修复

- JSON 选择改为追加，按规范化物理路径去重，并明确提示忽略数量。
- 支持一次多选、分批追加、删除、上移、下移和可见的项目映射顺序。
- 数量变化保留已有列表；不足和超出都给出明确状态，并禁止创建。
- 创建页只初始化一次资源状态，切页不再同步重复文件检查和重建控件。
- 新增 `logs/app.log` 轮转日志，记录启动、切页、文件选择数量、创建开始、成功、失败和未捕获异常。
- QSettings 新增按项目组路径保存最后选中项目。

## 验收结果

### 6 项目 + 6 JSON

两批追加 A/B/C 和 D/E/F 后显示 6 / 6。将 F.json 上移后真实创建，最终映射为：项目1=A、项目2=B、项目3=C、项目4=D、项目5=F、项目6=E。六个项目目录全部存在，每个“原始需求”目录只有对应 JSON，文件内容与源文件一致，无丢失、覆盖或错配。

一次选择 A-F 六个 JSON 的场景也完成真实创建，直接显示 6 / 6。

### 异常与稳定性

- 文件选择器连续取消 10 次后页面状态和已选文件不变。
- 重复选择会被忽略，不生成重复映射。
- 6 改 4 不删除文件并提示超量；4 改 8 显示还需 2 个。
- 删除、上移、下移后映射即时更新。
- 非法 JSON 和已存在目标目录均被拒绝，不产生部分项目目录。
- 创建页与首页往返 20 次，页面实例和子控件数量稳定，资源状态未重复检查。
- 重启后恢复最后项目；记录失效时回退项目1。
