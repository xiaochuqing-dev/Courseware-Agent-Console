本次完成了项目结构、创建体验、安全删除、失效项目组、单实例和文件夹改名恢复的综合修复，并针对删除弹窗无法关闭的严重问题追加了专项修复。

二、项目结构与兼容处理

新项目统一使用“原始需求、客户反馈、产品迭代”三个业务目录。

项目组配置升级为 schema v2，并增加稳定 group_id。项目移动后可通过 group_id 重新关联，不再只依赖易变化的绝对路径。

旧结构不会静默修改。用户确认后先保留同级完整备份，再迁移到新结构；遇到同名文件时保留双方内容，不覆盖用户数据。

任意一个或多个标准文件夹被手动改名后，产品会列出缺失目录和未知目录，让用户逐项选择对应关系后修复。无法可靠判断时不自动猜测。

三、创建体验

创建过程已放到后台线程执行，界面不会假死。

工具预验证结果会复用，避免创建时重复执行；创建按钮在运行期间禁用，防止重复点击生成重复项目。

创建页显示真实阶段，包括工具验证、复制公共工具、复制原始需求、生成项目结构和完成状态。

Node 子进程以隐藏窗口方式运行，不再闪出命令行窗口。

完整产品验收改为“完整验收（可选）”，适合多轮修改或正式交付前使用，不再阻塞日常归档流程。验收摘要仍会写入项目记录。

四、安全删除与本次严重问题

删除项目组改为整体移到 Windows 回收站。只有移动成功后才清除控制台登记；移动失败时原目录和登记都保持不变。

删除流程现在为“移到回收站”后再显示“确认移到回收站 / 取消”，不再出现备份提示，也不要求输入项目组名称。

严重问题的根因是项目目录已经进入回收站后，窗口激活事件仍尝试刷新旧路径。错误弹窗关闭时再次触发激活刷新，于是立刻生成同一个“项目组目录不存在”弹窗，造成 OK 和右上角关闭按钮都无效的假象。

修复后，删除和迁移期间禁止激活事件自动刷新；旧路径消失时项目页不再递归刷新；错误弹窗增加防重入保护；删除成功后切换其他项目组时不会自动触发旧结构备份迁移窗口。

五、失效项目组与单实例

启动时会清理不存在的登记项，同时保留 group_id 和最近项目线索，便于用户选择移动后的目录重新定位。

只有项目目录完整且身份一致时才恢复关联，避免误绑定同名目录。

程序使用 Qt 本地通信实现单实例。再次启动时第二个进程会退出并唤醒已有窗口。
