# 课件 Agent 控制台

Windows 桌面端规则自动化工具，当前版本 v1.1.0。已完成项目组创建、首次制作、多轮客户反馈、独立批量反馈、可选完整验收、手动归档、已完成项目查看及工作流优化 Prompt 闭环。GUI 只执行确定性文件规则，不接入任何模型 API。

当前项目页只负责当前任务、单项目反馈历史、单项目反馈导入、最新产品和验收状态。反馈区只有一个“反馈轮次”下拉框：默认选中最新轮次，切换后立即刷新该轮材料；材料列表使用固定高度和内部滚动，历史轮次再多也不会无限拉长页面。向旧轮次追加材料时，目标就是下拉框当前选中的轮次；“创建并保存为下一轮”始终使用当前最新轮次加一，成功后自动选中新轮次并进入“反馈修改”模式。

任务类型使用明确的“首次制作 / 反馈修改”业务类型，不再依赖按钮数字索引。选择反馈轮次、新建或追加反馈、以及从批量结果返回项目时都会自动进入反馈修改上下文。反馈任务必须绑定明确轮次、完整材料清单、最新有效产品和特殊要求；没有有效产品时禁止生成。项目已有有效产品和反馈轮次时，如主动切回首次制作，生成前会明确警告，不能静默覆盖反馈任务。

每次生成任务都会同时写入“当前任务快照.json”，记录项目身份、任务类型、反馈轮次、特殊要求、原始需求、反馈材料、最新产品、工具绑定、批量上下文、预期输出和 SHA-256。生成后立即自校验，复制执行指令前再次重算；材料、特殊要求、产品、项目路径、项目配置、项目记录、工具或批次记录发生变化后，旧任务会显示为已过期，仍可预览但不能复制执行。旧版仅有“当前任务.md”而没有结构化快照的任务也会被标记过期。

批量反馈是左侧入口进入的独立页面，不依赖当前单项目。页面使用真实、整格可点击且自绘高对比状态的复选框，表格同时显示课件名称、当前最新轮次、独立目标轮次和本课件提示。批量轮次规则固定为“每个选中课件独立创建各自下一轮”，不再提供追加策略，也不要求轮次数字一致。

共享材料先复制到项目组内临时区并核对大小与 SHA-256，全部准备成功后才写入各项目自己的新轮次。失败时整批回滚，不改动历史反馈。成功记录保存在“项目组/批量反馈/批次-时间-唯一后缀/批量反馈记录.json”，每个项目轮次中另有包含批次 ID、稳定项目 ID、项目提示和防串项目边界的说明文件。批量保存结果为每个项目提供“查看项目”按钮，可返回当前项目页并自动选中本批创建的轮次。

批量保存后可为每个项目分别生成自己的“当前任务.md”和“当前任务快照.json”，并生成批次级“批量反馈任务.md”。任务、快照、项目配置和批次记录采用统一暂存、替换与失败恢复；“复制批量执行指令”会重新核对批次语义、材料、每个项目任务和快照哈希，任一文件变化都会拒绝复制。

DOCX 和 DOC 始终作为原始客户材料原样复制，不移动、不重命名、不修改源文件，也不依赖本机安装 Microsoft Word。DOCX 只校验基础容器与关键文档部件，DOC 不解析正文；控制台不承诺完整理解图片、文本框、批注、修订、页眉页脚或嵌入对象，不支持 DOCM，也不会生成不完整替代文本冒充原始 Word。

标准项目目录只包含“原始需求”“客户反馈”“产品迭代”三个业务目录。旧版“工作文件 / 最终交付 / 验收记录”结构会按原样打开，不自动备份或迁移。项目内文件夹被改名或删除时，控制台只在异常首次出现或发生变化时显示一次短暂提示；同一异常在重启后也不会重复，恢复正常后再次异常才会重新提示。提示位于客户反馈区顶部，不弹出阻塞窗口，也不自动修改用户文件。

创建项目组时，每个 JSON 映射都可以独立绑定零个或多个首次制作材料。支持图片、PDF、Office 文档、文本和任意其他文件；同一文件可主动绑定到不同项目，项目内按规范化物理路径保序去重。材料只复制到对应项目的“原始需求”，不会移动或修改源文件。创建前会统一检查文件存在性、普通文件类型、可读性和同名冲突；复制后会核对大小与 SHA-256。项目配置的 source_materials 只记录文件名、大小、哈希和稳定 ID，不保存用户源文件绝对路径；旧配置缺少该字段时按空数组兼容。

项目创建时必须显式选择本机真实 workflow、template 和 validate。仓库与安装资源不保存或分发用户的私人公共工具文件；自动化测试只在系统临时目录动态生成公开的最小夹具。

创建和工具预验证在后台线程运行，界面显示真实阶段并阻止重复提交。Windows 子进程静默运行。项目组本地删除使用系统回收站，成功后才清理控制台记录。正式启动为单实例，重复启动会唤醒已有窗口。

工作流优化页支持“从项目复盘”和“人工提出优化”两种方式。人工优化只要求填写自然语言说明，可选图片、PDF、HTML、Markdown、Office、文本、代码或其他普通文件。控制台只复制材料，不移动或修改源文件，并将固定任务写入：

```text
工作流优化/当前优化任务.md
```

补充材料保存在“工作流优化/补充材料”。生成新任务前，上一轮任务和材料会完整归档到“工作流优化/历史优化任务/时间目录”。同一物理文件会保序去重；不同源文件同名、文件缺失、目录冒充文件、不可读取或复制校验失败时会停止生成并保留上一轮有效任务。

“复制执行指令”统一用于首页首次制作、首页反馈修改和人工工作流优化。它只复制包含真实绝对任务路径的短指令，不重新生成或改写任务；当前任务不存在、上下文不匹配或快照校验失败时按钮禁用并显示明确原因。

## 运行环境

- Python 3.11+
- PySide6 6.x

安装并启动：

```powershell
python -m pip install -r requirements.txt
python app.py
```

运行核心检查：

```powershell
python -m pytest -q
python app.py --smoke-test
```

阶段三完整回归与截图：

```powershell
python scripts\capture_phase3_screens.py
```

首次材料功能 GUI 验收与截图：

```powershell
python scripts\capture_initial_materials_screens.py
```

截图写入 artifacts，覆盖无材料页面、多项目不同材料数量、单项目多材料、冲突提示和创建完成首页。首次制作任务会要求 Agent 先枚举“原始需求”中的全部文件，JSON 作为结构化主需求，其他文件作为补充内容和视觉参考；无法读取的二进制材料必须如实记录。

人工工作流优化与复制执行指令 GUI 验收：

```powershell
python scripts\capture_manual_workflow_screens.py
```

该脚本验证空材料、多材料、任务生成结果，以及首次制作和反馈修改的“复制执行指令”，并在 artifacts 中生成五张验收截图。

反馈工作流重构 GUI 验收：

```powershell
python scripts\capture_feedback_workflow_screens.py
```

该脚本覆盖无反馈空状态、两轮历史切换、待保存材料与集中操作、新轮次自动绑定、独立批量页、真实复选框选中差异、各项目独立目标轮次、批量保存结果和结果跳转，并在 artifacts/feedback_workflow_refactor 中生成验收截图。

构建 Windows standalone 版本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build_windows.ps1
```

界面左侧显示“v1.1.0 · 短 commit SHA”；开发模式读取本地 Git SHA，正式构建会临时注入 resources/build_info.json，并在打包完成后恢复工作区。可据此确认 EXE 对应的版本、提交和构建日期，不依赖运行时网络。
